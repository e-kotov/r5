Fork prerelease of R5 7.6 for very large regions. Based on v7.6.1-ek.1 (R5 7.6 plus the deterministic Monte Carlo
seed option). Routing algorithms and dependencies are unchanged.

## What changed

Two independent size guards are now configurable through JVM system properties, with much higher defaults.
**Raising one does not raise the other.**

| Guard | Property | v7.6.1-ek.1 | This release | Accepted values |
|---|---|---|---|---|
| Rough WGS84 bounding-box area (OSM street layer, GTFS, freeform points, uploads) | `-Dr5.maxBoundingBoxAreaSqKm` | 10,000,000 km² | **100,000,000 km²** | > 0 and ≤ 510,000,000 |
| Cells (`width × height`) in any Web Mercator grid (whole-network grids, r5r `isochrone()` grids, destination/opportunity grids) | `-Dr5.maxGridCells` | 50,000,000 | **1,500,000,000** | integer 1 … 2,147,483,639 |

* Invalid, malformed, non-positive, overflowing or out-of-range values fail with an `IllegalArgumentException` that
  names the property. Nothing silently falls back to a default.
* The grid cell count is computed in checked `long` arithmetic before comparison. Before, `width × height` was an
  `int` product, so e.g. a 65,536 × 65,536 grid wrapped to 0 and passed. Negative dimensions and grids larger than the
  world at their zoom level are rejected. Other code that multiplies grid dimensions now uses checked arithmetic too.
* Latitude (|lat| ≤ 80), antimeridian and zoom (9–12) validation are unchanged.
* The release step now also uploads a `.sha256` file for the JAR.

## Configuration

r5r (before `library(r5r)`):

```r
options(java.parameters = c("-Xmx64G", "-Dr5.maxGridCells=2000000000"))
options(r5r.r5jar = "/path/to/r5-v7.6.1-ek.2-all.jar")
library(r5r)
```

Java: `java -Xmx64G -Dr5.maxBoundingBoxAreaSqKm=50000000 -Dr5.maxGridCells=2000000000 -jar r5-v7.6.1-ek.2-all.jar`

Restore the previous fork limits with `-Dr5.maxGridCells=50000000 -Dr5.maxBoundingBoxAreaSqKm=10000000`.

1.5 billion. Bounds, provenance, zoom 10 counts and memory estimates are in `docs/large-extents.md`.

## Limitations

* **Acceptance by the guards does not mean a region fits in memory or has been routed successfully.** Continent-scale
  network builds and routing have not been tested in this release.
* Memory grows with the number of cells: one street-mode linkage of a grid is 16 bytes per cell (19.5 GB for the
  Europe extent above), and travel time results and other per-cell arrays come on top of that. See
  `docs/large-extents.md`.
* Grids are limited to 2,147,483,639 cells by Java `int` array indexing. Europe at zoom 10 (3.0–4.9 billion cells)
  cannot be admitted by any configuration.
* Single-point travel time surface files (`TimeGridWriter`) are still limited to 2 GiB. Opportunity grid uploads are
  still limited to 10⁹ pixels × layers. Both limits are unchanged.
* The separate default detailed-car A* correctness issue is not addressed in this release.
